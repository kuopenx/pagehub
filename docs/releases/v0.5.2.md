# Pagehub v0.5.2

[English](https://github.com/kuopenx/pagehub/blob/v0.5.2/docs/releases/v0.5.2.md) · [简体中文](https://github.com/kuopenx/pagehub/blob/v0.5.2/docs/releases/v0.5.2.zh-CN.md)

New pages record only their creator. `updated_by` is omitted from saved metadata and MCP responses at revision 1, and the Dashboard shows only Created by. The first successful update or patch creates revision 2 and records the updater; subsequent writes keep the latest updater. Failed writes do not introduce an updater or advance the revision.

Older releases incorrectly initialized the updater during creation. Pagehub now ignores that field when loading revision-1 records, without rewriting existing files. Their Dashboard and MCP responses also omit the updater until an actual update. Creators, page IDs, URLs, content, revisions, and tokens remain compatible.

MCP create still requires `created_by`; update/patch still require `updated_by`. Clients must handle an absent `updated_by` in page responses. Refresh tools after upgrading to load the updated output schema and instructions.

## Install or upgrade

This is a source-only release without uploaded binaries or installers.

With Homebrew:

```sh
brew update
brew upgrade pagehub
pagehub setup
pagehub doctor
```

With Go 1.26.0+ on macOS or Linux:

```sh
go install github.com/kuopenx/pagehub/cmd/pagehub@v0.5.2
pagehub setup
pagehub doctor
```

Refresh the Dashboard after upgrading the managed service. New installations can use `brew install kuopenx/tap/pagehub`.

## Validation

Full race tests, vet, build, and real CLI/MCP acceptance passed locally. Regression checks cover creator-only creation, omitted updater metadata/responses, first update and patch, atomic failures, compatibility with old revision-1 records, and Dashboard visibility. macOS/Linux CI and the source-release workflow validate the tagged source before publication. Screenshot acceptance is unavailable locally.
