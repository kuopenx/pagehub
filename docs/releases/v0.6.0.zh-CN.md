# Pagehub v0.6.0

[English](https://github.com/kuopenx/pagehub/blob/v0.6.0/docs/releases/v0.6.0.md) · [简体中文](https://github.com/kuopenx/pagehub/blob/v0.6.0/docs/releases/v0.6.0.zh-CN.md)

其他设备上的 MCP 客户端现在可以携带有效的 Bearer token，连接 `http://<服务器局域网IPv4>:8765/_mcp`。MCP 只校验令牌，不限制来源 IP、Host 或 Origin。本机客户端注册继续使用 loopback；浏览器 CORS 响应头保持不变。

## 独立设备令牌

在 Pagehub 主机上执行令牌维护命令：

```sh
pagehub token generate --name laptop
pagehub token generate --name phone
pagehub token list
pagehub token show --name phone
pagehub token status --name phone
pagehub token rotate --name phone
pagehub token revoke --name phone
```

只有 `generate`、`show`、`rotate` 输出指定令牌供复制。列表只显示名称和状态，不显示秘密值。命令支持 `--data-dir` 和 `--json`，服务停止时也能使用；输出失败返回非零退出码，错误信息不包含令牌。

原令牌保留在 `<数据目录>/token`，名称为 `default`；省略 `--name` 的命令维护它。新增设备令牌私密保存于 `tokens.json`。为有效名称执行生成命令会复用原值。更换或废弃只使该令牌的后续请求失效，无需重启；已经通过认证的操作可能完成。废弃状态在 Setup 和重启后保留。其他设备令牌照常使用，即使默认令牌已废弃。所有令牌拥有相同的六个工具权限，共享同一批页面。

页面、URL、修订号和模型归属记录均保留。页面和 Dashboard 仍无需凭据即可访问。用于可信局域网上的可信内容；HTTP 不加密令牌。`connect` 和 `doctor` 仍使用默认令牌，所以主动废弃它后，即使设备令牌正常，`doctor` 也会报告问题。

## 安装或升级

本版本仅发布源码，不上传二进制或安装包。

使用 Homebrew：

```sh
brew update
brew upgrade pagehub
pagehub setup
pagehub doctor
```

macOS 或 Linux 使用 Go 1.26.0+：

```sh
go install github.com/kuopenx/pagehub/cmd/pagehub@v0.6.0
pagehub setup
pagehub doctor
```

升级后运行 `setup` 替换托管后台程序，保留现有页面、配置和原令牌。新安装可使用 `brew install kuopenx/tap/pagehub`。
