# Pagehub v0.4.1

[English](https://github.com/kuopenx/pagehub/blob/v0.4.1/docs/releases/v0.4.1.md) · [简体中文](https://github.com/kuopenx/pagehub/blob/v0.4.1/docs/releases/v0.4.1.zh-CN.md)

Fix Linux setup on distributions such as Fedora that ship global systemd user-service drop-ins. Version 0.4.0 incorrectly treated every drop-in as a foreign installation and refused setup.

Pagehub now accepts distribution-wide defaults directly under `/usr/lib/systemd/user/service.d/` or `/lib/systemd/user/service.d/`. These files remain unchanged. Foreign units, unit-specific drop-ins, and administrator/user overrides remain protected and are rejected.

## Install or upgrade

This is a source-only release with no uploaded binaries or installers.

On macOS with Homebrew:

```sh
brew update
brew upgrade pagehub
pagehub setup
pagehub doctor
```

With Go 1.26.0+ on macOS or Linux:

```sh
go install github.com/kuopenx/pagehub/cmd/pagehub@v0.4.1
pagehub setup
pagehub doctor
```

Do not remove Fedora’s global configuration to work around the old error. If setup still rejects a drop-in, check its path: service-specific and local overrides are intentionally protected.

## Validation

Full race tests, `go vet`, and real macOS CLI/MCP acceptance passed. Real Linux systemd acceptance passed in Lima with a temporary Fedora-style vendor global drop-in, including repeated setup, lifecycle commands, migration, uninstall, and all six MCP tools. The global configuration remained unchanged. Regression tests verify rejection of service-specific, administrator/user, mixed, and malformed drop-in paths. This reproduces Fedora’s configuration pattern on Ubuntu; it is not a full Fedora 44 installation test.
