# Pagehub v0.4.0

[English](https://github.com/kuopenx/pagehub/blob/v0.4.0/docs/releases/v0.4.0.md) · [简体中文](https://github.com/kuopenx/pagehub/blob/v0.4.0/docs/releases/v0.4.0.zh-CN.md)

Pagehub 现在同时支持 macOS 和 Linux 后台服务。`pagehub setup` 在 macOS 上选择用户级 LaunchAgent，在 Linux 上选择用户级 systemd unit，启动服务、启用登录自启动，并等待托管进程的健康响应。

## 更新内容

- Linux 支持重复安装、服务状态查询/启动/停止/重启、doctor、服务名称与端口迁移及卸载。服务状态显示登录自启动是否启用。
- Linux 升级失败会恢复旧可执行文件、设置、unit、运行状态与自启动状态。卸载会禁用本实例的服务，并保留页面、设置、令牌和客户端注册。
- Linux 启动支持含空格、引号、百分号和美元符号的路径。显式启动和回滚可以从 systemd 失败状态及启动频率限制中恢复。
- 拒绝其他安装的 systemd unit 和 drop-in。目前仅支持 macOS 和 Linux，两个平台均可前台运行。
- Linux CI 与源码发布验收现在验证真实用户级 systemd 服务和全部六个 MCP 工具。

Linux 后台管理需要 systemd 240+ 和可用的用户会话/bus。如果需要在登录前启动、退出登录后持续运行，可按需自行执行 `loginctl enable-linger "$USER"`。Pagehub 不修改 linger 设置。

页面和 Dashboard 仍默认监听 IPv4 `0.0.0.0:8765`；MCP 管理接口仍仅允许经过认证的 loopback 请求。既有页面、UUID、URL、创建时间、令牌和修订号保持兼容。

## 安装或升级

本版本**仅发布源码**，不上传预编译可执行文件或安装包。GitHub 自动提供源码 ZIP 和 tar.gz 归档。

macOS 使用 Homebrew：

```sh
brew install kuopenx/tap/pagehub
# 已安装用户：brew upgrade pagehub
pagehub setup
pagehub doctor
```

macOS 或 Linux 使用 Go 1.26.0+：

```sh
go install github.com/kuopenx/pagehub/cmd/pagehub@v0.4.0
pagehub setup
pagehub doctor
```

通过 `pagehub connect codex` 或 `pagehub connect claude` 连接客户端。前台实例需重启以使用新可执行文件。

## 验证

实现已通过 macOS 和 Linux ARM64 上的完整 race 测试、`go vet`、构建及真实 CLI/MCP 验收。额外的 Linux 虚拟机测试覆盖了已启用 linger 时的关机再开机自启动、后台运行、daemon reload、进程恢复、成功升级与失败回滚、数据持久性、外部 unit 保护、重复卸载及宿主机直连虚拟机页面；LAN MCP 请求按预期被拒绝。CI 也会在发布前验证 Linux 和 macOS。
